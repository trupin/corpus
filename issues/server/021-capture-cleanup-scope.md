# [SERVER-021] Capture cleanup deletes committed attachment bytes on post-commit failure

## Summary

`apps/server/src/capture/capture.ts` wraps everything after `storeTurnFiles` in one try/catch whose cleanup runs `removeTurnAttachments` for ANY later failure — including failures after `runMutation` has committed the inbox doc and filing thread (e.g. `enqueueComment` on an unwritable `.corpus/queue/`, or the read-back `loadDocument` throwing). Result: a committed turn permanently references deleted files — the exact state the module's own header forbids. Also fix the same-session contract rider consumer: `MarkSeen` handler must return the real `unread` (see CONTRACT-010) once the schema is a boolean.

## Acceptance Criteria

- [x] Attachment cleanup runs only for failures BEFORE `runMutation` commits; post-commit failures leave the bytes in place (the reference is committed; the bytes must stay).
- [x] Regression test: force a post-commit failure (e.g. unwritable queue dir) → 500 to the client, but the attachment files still exist and the committed turn's references resolve.
- [x] MarkSeen handler returns computed `unread` per the CONTRACT-010 schema; the existing partial-mark logic in `query.ts` is the one source of truth.
- [x] Full gate green.

## Technical Design

Split the try/catch at the `runMutation` boundary in `capture.ts` (and mirror in the turn-append ingest path if it shares the shape). MarkSeen: reuse the unread computation `GET /api/docs` uses.

### As implemented

**1. Cleanup scope.** The cleanup is now a named guard, `whileUnreferenced(attachmentsRoot, threadId, turnTs, stored, build)` in `apps/server/src/threads/turns.ts`, wrapping **only the markdown-building** — the window in which nothing anywhere references the bytes. Both multipart surfaces use it: `appendThreadTurn` (same file) and `captureDocument` (`apps/server/src/capture/capture.ts`), which shared the defect verbatim.

`runMutation` is **outside** the guard rather than at its edge. It writes, commits and re-projects behind one call, and a caller catching its rejection cannot tell which of those it got past — so treating "it threw" as "nothing is committed" would leave a narrower version of the same bug (a projection failure after the commit). The accepted cost is the mirror image and the cheaper one: a `runMutation` that fails during its *write* phase rolls the markdown back and leaves the bytes with nothing pointing at them. Unreferenced files in a gitignored directory are litter; a committed reference to bytes that are gone is corruption.

**2. MarkSeen `unread`.** `docs/needs.ts`'s `UNREAD_SQL` is now generated by a private `unreadSql(mark)` with the compared mark left to the caller: the collection query passes `s.last_seen_ts` (the emitted string is byte-identical to what it was), and the new `isThreadUnread(db, threadId, mark)` binds `@mark`. `recordMark` calls it at **both** return sites, always against the mark it is *reporting* — `requested` on the main path, the mark on record for a rejected backwards mark. One fragment, so the response and the next `GET /api/docs` cannot disagree.
