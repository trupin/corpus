## Observations (outside the acceptance criteria — not failures of these issues)

- **O1 — A fast paste after a click lands at the earlier selection.** The cause is not UI-202. A note that was never in the viewer shows the same result. Click "After the picture." and press Cmd+V at once: the result is `PASTEDBefore the picture.`. A 100 ms pause puts the paste at the caret. Typing does not show this, because it lands at the caret (U2). Nothing is lost, but the text lands in the wrong place. It may deserve its own issue. UI-202's log names paste as "not exercised" and assumes it takes the same path as typing. It does not take the same path.
- **O2 — Space on the focused image does not open the viewer.** Enter does. The image has `role="button"`, and the ARIA button pattern starts the action on Space as well. The spec does not name the key, so this is not a failure. This evaluation did not test whether v0.37.0 behaves differently.
- **O3 — After the viewer closes, Backspace closes the reader.** Focus goes back to the image (§10). Backspace then closes the reader, and so does Escape. Backspace also closes it when focus is on the image and the viewer was never open. Nothing is lost on disk. The cause is not UI-202's fix, but a reader closing on Backspace may surprise a user.
- **O4 — Path variants outside the defined list still get the shell with the token.** `GET /openapi.json/` (trailing slash), `GET //openapi.json` and `GET /OPENAPI.JSON` each return `200 text/html` with the token in the body. `/doc/` returns the shell by the issue's stated decision. This adds no exposure: `curl /` has returned the token since SERVER-024, by design. So SERVER-169 fixes the wrong answer on conventional paths, and does not hide the token from a local process. The issue's criterion is "a defined set", and the set holds.

## Summary

The evaluation passed 16 of 16 criteria rows (11 for UI-202 and 5 for SERVER-169).

- **UI-202.** The image survived every sequence: type at once, click then type at once, human-speed typing, paste with focus on the image, click then paste, backdrop close, and 50 stress cycles. Each result was checked in the DOM and in the file on disk. Right-click and keyboard opening still work.
- **SERVER-169.** All six named paths answer with a tokenless 307 or a JSON 404 over GET and HEAD. The real document still works with the token. Deep links and `/` still load and authenticate after a hard reload.

Four observations are recorded for triage. None of them is a failure of these two issues.
