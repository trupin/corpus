Surveyed after v0.24.0, having gone untouched through three releases, and kept

is blocked by it.

## Summary

Filed out of SERVER-132, which shipped the right behaviour through the wrong
door and said so.

An ill-shaped `resident:` block makes a designation vanish from the roster.
SERVER-132 made that visible, but reported it through `corpus db doctor` rather
than `corpus doc check`, because `doc check`'s code list is a closed contract
enum whose every non-warning member blocks the write. Reporting there today would
mean either a new code — a contract change, which is this issue — or reusing
`frontmatter-invalid`, which would make the broken thread permanently unwritable.
That last is SERVER-123's regression verbatim and was correctly refused.

So the finding lives in the projection doctor, which is a health command a person
runs deliberately, rather than in the check a person runs on a document they are
editing. It is reported, but not where someone would look.

## Acceptance Criteria

- [ ] `CHECK_CODES` gains a `resident-malformed` member at **warning** severity,
      so `corpus doc check` reports it and does not block the write
- [ ] The severity choice is stated in the schema, not merely made: a designation
      is user-only state, and refusing the write would trap the thread
- [ ] With the code declared, the finding joins `REPORTED_CHECK_CODES` beside
      `unterminated-fence` and reaches `doc check` with no detail-string predicate
- [ ] `openapi.json` and the typed client regenerated, not hand-edited
- [ ] A follow-up server issue moves the finding, or records why the doctor
      report stays alongside it

## Technical Design

Note the interaction with CONTRACT-084 and SERVER-067, which put tolerated
errors on the mutation response. If `resident-malformed` is a warning rather than
a tolerated error, it travels the existing warning path and needs nothing from
that work.

## Testing Strategy

Contract-side: the code is declared, `codes.test.ts`'s partition assertions still
hold, and `openapi.json` regenerates cleanly.

## E2E Verification Log

Implemented on: **opus**.

### Scope: the whole thing, not the contract half

The issue's last criterion left the server work to a follow-up. That would have
shipped a declared enum member nothing emits — a code in the published
vocabulary that `doc check` can never return, which is the exact class of "the
product says something that is not so" this repository keeps closing. So the
code is declared, **emitted**, and reported on the write path, in one change.

An existing test made the point before I did. `codes.test.ts` asserts the
partition **from behaviour** — it builds a corpus and compares the report's
warning codes with the contract's tuple — so adding the code to the contract and
not to the validator turned it red. The guard is right: a warning nothing emits
is not a warning.

### Post-Implementation Verification

Real server, real workspace, port **8766**. A standalone thread whose
`resident:` block says `name: 42`:

```
$ corpus doc check th_badres1
warning resident-malformed data/threads/th_badres1.md: `name`: Invalid input: expected string,
  received number; `docId`: Invalid input: expected string, received undefined
checked 1 document — 1 warning, no errors.
$ echo $?
0
```

It reports where a person editing the document would look, names the failing
keys, and **exits 0** — which is the severity decision made visible.

The thread stays writable, which is the point of the severity:

```
$ corpus doc edit th_badres1 --title "Renamed anyway" --from user
edited th_badres1
key 9f3f759…
```

An error here would have made that thread permanently unwritable — SERVER-123's
regression in a second shape, and the reason reusing `frontmatter-invalid` was
correctly refused when this was filed.

**The doctor still reports it too**, in its own longer words with the repair
(`corpus thread designate`). The two are not duplicates: the doctor is a health
command somebody runs deliberately over the whole workspace, and the check is
what runs on a document somebody is editing and on every save. This issue's last
criterion asked for one or the other to be recorded — the answer is that the
doctor report stays.

### Suites

`packages/contract` 3,103 passed, 71 files. `apps/server` 4,791 passed, 210
files. `openapi.json` and the typed client regenerated by `npm run generate`,
never hand-edited — and the regeneration is what let the server compile at all,
since the route's response type refuses a code the contract does not declare.

**Four enumerated guards had to be updated**, each of which exists to make a
silent addition impossible: the codes-and-count pair in `codes.test.ts`, the
ordered list and the partition in `check.test.ts`, the published enum in
`openapi.test.ts`, and the cross-partition assertion in `warning.test.ts`. That
is the drift machinery working rather than four chores.
