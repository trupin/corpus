## Domain Knowledge

- **`exactOptionalPropertyTypes` optional-widening asymmetry (2026-07-31, CONTRACT-025):** `z.infer` widens optionals to `?: T | undefined` while `openapi-typescript` emits `?: T` (zero `| undefined` across the generated client's optional properties). Zod-inferred types are assignable _from_ generated ones, never _to_ them — uniformly, for every optional field. Write compat tests against hand-transcribed generated shapes, not schema-derived ones.

- **Never `.nullable()` a registered component (2026-08-08, CONTRACT-037):** the safe spelling for a nullable reference to a named schema is `z.union([X, z.null()])`, **never** `X.nullable()`. `zod-to-openapi` propagates a registered name onto derived schemas, so one route writing `lock: LockSchema.nullable()` silently rewrote the **shared** `Lock` component to `type: ["object","null"]` for every route referencing it. The union publishes `anyOf: [{$ref: Lock}, {type: "null"}]` and leaves the component plain. Caught by the "every named component is a plain, non-nullable, undefaulted object" invariant — which is there precisely because this is invisible at the call site. The same rule costs a discriminated union its component name (a `oneOf` has no `type: "object"`), so an act/variant union inlines rather than registering; `ContextPackSchema` already follows this.

_Durable facts, decisions, and gotchas for this domain. Append as you learn; keep entries dated._

- **2026-07-26 — Contract-first via code (Architecture Decision 3).** Routes are _defined_ here with `createRoute` from `@hono/zod-openapi`; the server imports the definitions and attaches handlers. The OpenAPI doc is _derived_ — never hand-edited. `openapi.json` and the generated client types are committed; **CI** regenerates and diffs (drift check). It was in pre-push until INFRA-025 moved it — regenerating needs a full build, so the drift check is now CI's and a hand-edited artifact survives locally until CI catches it. Run `npm run generate -w packages/contract` and diff before pushing.
- **2026-07-26 — Client shape.** `@corpus/contract/client` exports a factory taking `{ baseUrl, token }`, wrapping `openapi-fetch` over `openapi-typescript` types. Both `apps/cli` and `packages/kit`/`apps/ui` consume this — never a second client implementation.
- **2026-07-26 — Schemas are the only type source.** Resource types are `z.infer` of schemas here. If server or UI hand-declares an API shape, that's a bug to flag.
- **2026-07-26 — Non-fetch surfaces.** SSE (`/events`) and multipart attachment upload get hand-written helpers beside the generated client; they're still documented in the OpenAPI doc.
- **2026-07-27 — The frontmatter surface is split: closed core, open `extra` (CONTRACT-011).** §10's view keys (`pinned`, `order`, `query`, `column`) are first-class core fields — `pinned` filters and `order` sorts, so they can never be opaque. Everything else non-core rides the flat `extra` object (`schemas/extra.ts`): values typed `unknown` — the server never interprets them, so a document carrying a key the core does not define costs zero contract changes — bounded plain JSON (≤ 8 containers, ≤ 64 KiB), `RESERVED_FRONTMATTER_KEYS` (18) rejected inside it on both requests and responses, update = shallow RFC 7386 merge patch (`null` removes a key). The schema descriptions are the published contract; `openapi.test.ts` pins their prose.
- **2026-07-27 — Open-record schemas stay unregistered.** `ExtraFrontmatterSchema` and `ViewQuerySchema` are deliberately not `.openapi("Name")`-registered components: they are used `.nullable()`/`.optional()`-derived, and zod-to-openapi propagates a registered name onto derived schemas, silently rewriting the shared component (the non-nullable-component invariant would catch it, but inlining removes the hazard). Inline duplication in `openapi.json` is deterministic and fine.
- **2026-07-27 — Read exit codes from the tool, never a pipeline.** Recorded in CONTRACT-009 and re-relied on here: `cmd | tail; echo $?` reports `tail`'s exit. Redirect to a file and echo `$?` immediately.
- **2026-07-29 — Form fence grammar is settled: a CommonMark subset, restrictions only (CONTRACT-014).** `findFormFence` (line scanner in `schemas/form.ts`) is the one grammar; the old `FORM_FENCE_PATTERN` regex is deleted. Rule: match only what CommonMark would render as a `form`-info code block, under three documented restrictions (column-0 fences only; backtick fences only; closing fence required — no EOF-close). Restrictions may only ever _decline_ CommonMark-valid fences (safe degrade to a code block everywhere at once) — never match where CommonMark wouldn't. Any future grammar change requires a server `SCHEMA_VERSION` bump (projected `turns.has_form` is derived from it; bumped 4→5 with this change).
- **2026-07-29 — SSE token-in-query is a decided v1 posture (CONTRACT-014).** Accepted under the localhost bind; rationale + the remote-deployment boundary live on the `/events` route docblock. Client error messages must carry `redactedUrl()` (token masked) — errors are what callers log. A remote-server setup swaps to a short-lived ticket/cookie behind `createEventStream` without a signature change. A SPEC §9.2 line was drafted and HELD for user sign-off (see the issue's E2E log).
- **2026-07-29 — Strict bodies, tolerant reads (CONTRACT-017).** Every request body schema is `z.strictObject` (unknown top-level key → 400 naming the key); openness lives one level down in open _values_ (`extra`, `ViewQuery`, event `payload`); query/path/header schemas stay tolerant; responses unchanged. Policy prose in `schemas/index.ts`; an `openapi.test.ts` sweep enforces `additionalProperties: false` on every published request body (≥15, non-vacuous). New bodies must be `z.strictObject` or the sweep fails.
- **2026-07-29 — formTs pairing deferral (CONTRACT-014).** The form answer turn deliberately does not name the form it answers; UI pairing after reload stays the order rule. Closing it needs machine markup in §6's deliberately-plain prose format → SPEC revision territory, and the failure is rare/visible/self-healing. Recorded in the `FORM_ANSWER_LABEL` docblock; do not "fix" silently. **Superseded in part 2026-08-07 (CONTRACT-038)**: the answer now names its questions, so pairing is by content and the residual is two open forms asking a literally identical question.
- **2026-08-07 — The form grammar is fields, and legacy collapses at the parse boundary (CONTRACT-038).** `FormSchema` is a union of the long spelling (`fields[]`) and the shorthand (`prompt` + `options`), where the shorthand **transforms** into one required `choose one` field — so `Form` is a single `{fields}` shape and no consumer ever branches on "is this an old form?". Three kinds only, spelled verbatim as §6 spells them (`choose one`, `choose any`, `write`) because the agent writes the YAML with §6 as its only reference. A field's identity is its question text (distinct within the form); no field ids, ever — the repetition is what makes the answer turn readable. Every object in the grammar is strict, so a typo (`optionnal`) fails loudly instead of silently meaning something else. Request and payload are deliberately **not** merged: the request omits a blank optional field, the payload keeps every field present with all value keys null (§7's "unanswered vs unasked").
- **2026-08-07 — `409`, not `400`, for a request the state refuses (CONTRACT-038).** Re-answering an answered form joins the repo's existing `409`s (taken skill name, deferring unclaimed work, second upgrade in flight). The rule: `400` tells a client "fix the body and retry"; when retrying with any body cannot help, `400` sends the caller in circles. Contract declares the response; the server enforces it.
- **2026-08-07 — A `.refine()` on a `z.strictObject` keeps `additionalProperties: false` (zod v4 + `@hono/zod-openapi@1.5`).** Verified against the generated `openapi.json` for `FormFieldAnswer`: zod 4 attaches checks to the schema rather than wrapping it in `ZodEffects`, so refinements survive registration and the CONTRACT-017 sweep stays non-vacuous. Prefer a strictObject + refine (good error messages) over a union of strict objects (`oneOf` + "invalid_union") when the published component should read as one shape.

- **2026-08-16 — One fact asked at two grains is one schema object, not two descriptions (CONTRACT-045).** `presenceLiveField`/`presenceSinceField` (`schemas/agents.ts`) are published on an `AgentLane` row _and_, via the `AgentPresence` component, on `QueueStatus.agent` — the same objects, so the two sites' prose is identical by construction. The drift test is written against the **generated** document by JSON pointer (`AgentPresence.properties.live === AgentLane.properties.live`), which is the only form that catches a hand-copied description. Two consequences worth remembering: a subject-neutral first sentence is the price ("on this lane where this sits on a roster row, on any lane at all where it sits on the queue status"), and the aggregate must state its identity with the per-row fact in published prose (`live` is true exactly when some lane's is) — otherwise the redundancy is just a number that can be wrong.
- **2026-08-16 — Adding a required response field is additive on the wire and breaking in TypeScript (CONTRACT-045).** Every _reader_ of `QueueStatus` compiled unchanged; every _constructor_ outside the package (server `status()`, the UI's `UNKNOWN_QUEUE_STATUS`, e2e stubs, test fixtures) failed to compile. That is the intended forcing function for the blocked-on server/UI issues, but it means the repo's typecheck is red between the contract landing and its consumers, so say so explicitly in the report rather than letting the harvest gate discover it. Fix your own workspace's fixtures (`routes/index.test.ts`, `client/index.test.ts` mount stubs) — leave the other domains' to their issues, which will rewrite those exact lines.
- **2026-08-16 — The contract may export functions, and sometimes must (CONTRACT-045).** `isAgentPresent`/`agentActivity` join `findFormFence` as behaviour shipped from the schema package. The test for whether a rule belongs here: it needs a constant the wire publishes (the presence window is derived from `MAX_IDLE_TIMEOUT_SECONDS` — corrected from `DEFAULT_…` by CONTRACT-060, below) _and_ has more than one consumer (the console pill and the CLI both read queue status). A rule with one consumer stays in that consumer.

- **2026-08-17 — Sameness of _remedy_ decides whether two refusals share an error code, not sameness of parameter (CONTRACT-058).** A `recipient` naming no lane and a `scope` naming no lane are one `unknown_recipient`, because both are fixed by "name a lane that exists, or name none"; `unknown_job` and `unknown_recipient` stay two codes because a bad job costs provenance and a bad lane costs routing, and those are different calls. `ERROR_CODES` is a published discriminant, so renaming a member to fit a later caller is a four-domain breaking change (CLI renderer, kit composer recovery, UI fixtures, server tests) — the fix for a name that has outgrown its origin is a **component-level `.openapi(name, {description})`** stating the fact parameter-neutrally and naming every parameter that reaches it. Put it in the published document, not only in the JSDoc: the reader who is confused by the name is reading `openapi.json`.
- **2026-08-17 — A declared-status sweep is a closed enumeration, not a call-graph analysis (CONTRACT-058).** Declared side: walk `openapi.json`'s `paths[p][m].responses`. Emitted side: the server's HTTP statuses come from exactly three closed sets — the `HttpError` factories in `apps/server/src/errors.ts`, the four direct `new HttpError(...)` constructions (`reattachConflict`, `patchConflict`, `destinationOccupied`, `fromHttpException`), and the middleware (`createBearerAuth` + `UNAUTHENTICATED_ROUTES`, `defaultHook`, `localhostOnly`/`noBrowserOrigin`, `createUploadSizeGuard`, `createRawAttachmentPathGuard`) — so `grep 'throw '` plus hand-resolving ~8 assert-helpers covers every route. Also cross-check the 55 contract route keys against `contractRoutes.<key>` references in the server: two upgrade routes are declared and unmounted, which makes the comparison vacuous for them. The sweep found a second gap the issue did not name — `PUT /api/docs/{id}` emits `403` on an agent detach and declares none — which is why "no others" is only worth saying after doing this.
- **2026-08-17 — The declared-vs-emitted cross-check cannot live here, and its home is one wrapper away (CONTRACT-058).** `packages/contract` cannot import `apps/server`; what _is_ expressible here is a document-side sweep (every declared `422` carries an `ApiError` member). The real check belongs in `apps/server/src/docs/write-fixture.ts` — the single seam every server integration test's `request`/`post`/`put`/`del` funnels through — asserting each response's status is declared for the matching operation, resolved with the server's own `createContractPathMatcher` over `ALL_CONTRACT_ROUTES`. One wrapper turns the whole existing server suite into the cross-check; per-route assertions would not have caught either gap.
- **2026-08-17 — A derived constant is only derived if exactly one place does the arithmetic (CONTRACT-060).** `AGENT_PRESENCE_WINDOW_SECONDS` was `DEFAULT_IDLE_TIMEOUT_SECONDS * 2` here while `liveness.test.ts` pinned `MAX_IDLE_TIMEOUT_SECONDS * 1000 * 2` — two derivations from two multiplicands, both green only because `DEFAULT === MAX === 480`. The multiplicand is the **max**: the default is what a client gets when it asks for nothing, the max is what every park is admitted under (`IdleQuerySchema` `.max(MAX)`, and the CLI segments at `min(remaining, MAX)`), so the longest gap between two contacts from a healthy listener is a max-length park. Two rules from this: (a) when a consumer must restate something, let it restate the **bound it relies on** (`> MAX * 1000`) and never the **derivation** (`=== MAX * 1000 * 2`) — the bound follows from any correct window, the derivation is a second opinion about the rule; (b) pin the multiple _and_ the property the multiple exists to deliver, worded without naming the wrong candidate ("survives a missed rearm at the longest park the contract permits"), or the assertion passes by coincidence for as long as the two constants are equal.
- **2026-08-17 — Prove a client-type claim with a counterfactual `tsc`, not a passing vitest (CONTRACT-058).** Vitest does not typecheck, so a test reading `error.recipient` passes whether or not the response is declared. Remove the declaration, regenerate, run `tsc --noEmit -p packages/contract`, and read the error: `TS2367` on `error?.code !== "unknown_recipient"` against a union of `"bad_request" | "unauthorized"` is the gap stated in the compiler's own words. Write the assertion as a **narrowing** (`if (error?.code !== X) throw`) rather than an optional-chained property read — the property read fails to compile in both worlds and proves nothing.
