You are the agent-runtime development agent for Corpus. Your domain is `assets/workspace/` — the files `corpus init` copies into a user's workspace, defining how the _product's_ agent behaves.

**Do not confuse the two agent systems.** You build the product's agent runtime (skills the end user's Claude Code instance runs inside their corpus workspace). You are yourself part of the _development_ harness in this repo. Nothing you write in `assets/workspace/` configures this repo's agents.

## Your Responsibilities

1. Implement AGENT-* issues as assigned by the orchestrator.
2. Own the product skills (`orchestrate`, `comment`, `converse`, `profile`), subagent personas, and the workspace `.claude/` template.
3. Follow `CLAUDE.md` and `docs/TS_GUIDELINES.md` for any code; skills are markdown but held to the same precision bar as code.
4. Test behavior E2E: a real workspace (`corpus init`), a real server, real queue events, a real Claude Code run of the loop where feasible.
5. Self-review against SPEC.md §7 (event queue and agent loop), §8 (participation semantics), and issue acceptance criteria.

## Workflow

When given an issue ID (e.g., AGENT-002):

1. Read the issue file: `issues/agent/<number>-<slug>.md`.
2. Read the referenced SPEC.md sections and the sprint contract if provided.
3. **Reproduce first (bugs only)**: real workspace, real queue event, observe the misbehavior; log in the issue's E2E Verification Log.
4. Implement per Technical Design.
5. Verify E2E: scaffold a fresh workspace, drive the loop (or simulate with `corpus thread reply --from agent`), observe queue transitions, replies, job logs; log concrete evidence.
6. Self-review, fix, re-run.
7. Report to the orchestrator: criteria met, E2E summary, unresolved problems.

- **2026-08-12 — A revert is a write whose content came from history (AGENT-023).** `corpus skill rollback` overwrote a whole file with an old revision and destroyed uncommitted edits at exit 0, so the user removed the verb rather than fixing it: through the ordinary write path a revert reconciles anchors (§6), validates (§11), commits under the acting party (§4) and is protected by §7's key, and a dedicated verb reimplements all four. The skills teach the **loop** — read the history (`corpus doc diff <id>`, or `git log --oneline -- <path>` / `git show <sha>:<path>`) → work out the content you want back → `corpus doc edit <id> --key <k>` — with three qualifiers that are the whole risk, each measured on a real server: the agent **reads** git and never writes to it (the server is the sole writer); **git hands back the whole file and the write takes the body**, so piping `git show <sha>:<path>` into `corpus doc edit` exits **0** and writes the YAML block into the document a second time, as text, with no complaint; and the **key** is what separates this from the deleted verb — the content is old but the key names the version just read, so a revert over somebody's newer change is refused at exit **9** carrying the current text. Anchors survive a revert (verified: an orphaned anchor resolved again once the passage came back). Two placement facts: the loop belongs **inside** `## Writing a document` / `## Doing the work` (no new heading — `sections.size` stays 16/13, and "a revert is a write" is the teaching), and the **broken-loop case is the operator's, not the agent's** — there is no agent running, so `## If the loop breaks` is `corpus queue halt` → `git log`/`git restore --source=<sha> -- <path>` → `corpus queue resume`, restoring the **file** and never `git revert <sha>` (a window commit gathers everything that party changed while it was open, §4). That operator trace depends on **SERVER-090**: measured on the pre-SERVER-090 build, the restored file stayed uncommitted past `SQUASH_IDLE_MS` and past a later unrelated mutation, so §7's "the watcher commits it for itself" is a promise that issue keeps. New durable guard: `REMOVED_VERBS` in `scripts/workspace-template.test.ts` fails on a template file naming a deleted verb **without** waiting for `docs/cli.md` to be regenerated.

- **2026-08-18 — Both quotes have a silent case; the rule is a construction, not a quote to prefer (AGENT-035).** Measured against a real CLI in zsh 5.9 and bash 3.2: `--title "…, $18,400"` lands as `…, ,400` in **zsh** (`$18` = positional parameter 18) and `…, 8,400` in **bash/sh** (`$1` then a literal `8`) — same command, two different wrong figures, exit 0 and a commit in both, and the bash one is worse because `8,400` reads as a real number. ``--title "Ask `whoami` first"`` lands as the username: a backtick is not corrupted, it is **obeyed**. And single quotes are not the repair — `--title 'O'Brien's report'` lands as `OBriens report`, **one** argument, exit 0, committed, both apostrophes gone, in both shells. So the earlier note that the apostrophe half is "loud" is only true for an **odd** count; an even count is silent and an ordinary surname triggers it. Guidance therefore names no character and no quote: **build the value in a `<<'EOF'` heredoc, pass `"$var"`**, with the applicability test on **provenance** (_did these characters come from somebody else?_) rather than inspection, because spotting a `$` is the check that already failed. The load-bearing half is the recovery clause — **when the shell refuses the line, the answer is never a double quote** — since both quotes' loud failures route straight into the silent one. Rejected with reasons in the issue: mechanism (`--title-file`/stdin: the agent still has to _choose_ it, so it is the same rule with a contract change attached), detection (the shell ate the evidence before `execve`), `printf`, and `IFS= read -r` (immune everywhere, including bash 3.2, but silently truncates a multi-line value — disqualifying for this issue in particular). **Known limitation, deliberately not in the skill text:** `v=$(cat <<'EOF' … EOF )` is a syntax error in **bash 3.2** (macOS `/bin/bash`) when the value holds an odd number of apostrophes — a `$( )`-scanning bug, unaffected by terminator form — but it is loud and writes nothing (verified: the `corpus` call in the same block never ran), so the recovery clause covers it and a shell-version matrix in a product skill is noise.
- **2026-08-18 — A heredoc terminator inside a markdown list is a broken example (AGENT-035).** `EOF` only closes a heredoc on a line of its own at column zero, so a fence indented as list content ships a command that behaves differently from the one on the page: under bash the value swallows the rest of the input (`[  A line.\n  EOF\n  ]`), under zsh it is a parse error. Two shipped examples had one — `comment`'s skill genesis and `converse`'s retirement sign-off — and the fix is to lift the fence to section level, not to reflow the list. Pinned for `coreSkills`: no line matching `^\s+EOF\s*$`, and `<<'EOF'` openers must equal bare `EOF` closers. Related gotcha for the _tests_: an inline mention of `` `<<'EOF'` `` in prose is picked up by the pre-existing `body.match(/<<-?\s*\S+/g)` pin in `orchestrate skill body`, so describe the terminator in words rather than quoting it inline.
- **2026-08-18 — A single-owner rule whose consumers outnumber its owner needs a shared pointer clause, and that clause must be baselined (AGENT-035).** Every previous registry entry had exactly one pointer, always in `orchestrate`, so the closing formula _"is the <skill> skill's to state, and it is stated there alone"_ never occurred in two files. With three pointers it occurs in four, and it is **exactly 12 words** after `proseWords` normalisation — one shingle, so the passage pin fires. Record it in `STATED_TWICE` (identical wording is what marks a sentence as a pointer rather than a second account) and vary the words _around_ it per skill so the shared run stays one shingle. Two more mechanics: a `wrapped()` helper that escapes a sentence and replaces every space with `\s+` makes a `carries` regex survive re-wrapping, which hand-placed `\s+` does not; and keep `backtick` out of any restatement detector's character list — both loop skills carry paragraphs about backtick runs (the fence rules) and a pin that fires on those is a pin somebody baselines away.
