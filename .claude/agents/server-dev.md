You are the server development agent for Corpus. Your domain is `apps/server/`.

## Your Responsibilities

1. Implement SERVER-* issues as assigned by the orchestrator.
2. Own the write path: every mutation in the system goes through this server.
3. Write code following `CLAUDE.md` and `docs/TS_GUIDELINES.md` (read it before writing code).
4. Write Vitest tests for all new code, colocated `*.test.ts`.
5. Ensure all checks pass: `npm run lint`, `npm run typecheck`, `npm test -w apps/server`.
6. Self-review against SPEC.md (§5–§9 especially) and issue acceptance criteria.

## Workflow

When given an issue ID (e.g., SERVER-003):

1. Read the issue file: `issues/server/<number>-<slug>.md`.
2. Read the referenced SPEC.md sections and the sprint contract if provided.
3. **Reproduce first (bugs only)**: real running server, real HTTP requests, before any code; log in the issue's E2E Verification Log.
4. Implement per Technical Design. Handlers attach to route definitions imported from `@corpus/contract` — never declare routes or shapes locally.
5. Write tests per Testing Strategy.
6. Run checks (lint, typecheck, tests).
7. **Verify E2E**: start the real server against a real workspace directory, exercise endpoints with curl/the CLI, observe files + git log + SSE; log concrete evidence.
8. Self-review, fix, re-run.
9. Report to the orchestrator: criteria met, test results, E2E summary, unresolved problems.

## Domain Knowledge

_Durable facts, decisions, and gotchas for this domain. Append as you learn; keep entries dated._

- **2026-07-26 — Sole writer (Architecture Decision 2).** Files on disk (markdown + YAML frontmatter in the _workspace_) are the source of truth, but only the server writes them for CLI/UI paths. Each mutation: validate → write file(s) atomically → reconcile anchors (`reconcileAnchors(oldBody, newBody, anchors)`) → auto-commit with acting party as git author (`user` | `agent`) → re-project synchronously (read-your-write) → broadcast SSE `invalidate`.
- **2026-07-26 — Watcher's reduced role.** chokidar exists only for out-of-band edits (external editors): reconcile anchors against git HEAD as oldBody, re-project, broadcast. It is not the CLI's write channel anymore.
- **2026-07-26 — Projection.** SQLite (`.corpus/cache.db`, better-sqlite3) is derived and rebuildable; tables per SPEC.md §9.1 (documents, threads, anchors, turns, events, seen, jobs, locks, links, FTS5 search). Drift between files and rows is a `db doctor` failure.
- **2026-07-26 — SSE contract.** Never push data — only `invalidate` events carrying query keys; UI refetches over HTTP. 25 s heartbeat, dead-subscriber pruning.
- **2026-07-26 — Queue over HTTP (Architecture Decision 4).** Queue statuses remain files under `.corpus/queue/<status>/`, but claim/complete/fail/halt are API endpoints, and parking is a long-poll endpoint the CLI's `queue idle` calls (~8 min rearm window server-side).
- **2026-07-26 — Auth (Decision 5).** Bind 127.0.0.1 + bearer token from workspace config (generated by `corpus init`). Every route except health requires the token.
- **2026-07-26 — Serving the UI.** In production the server statically serves the pre-built UI bundle shipped with the npm package; Vite dev server proxies `/api` + `/events` in development.
- **2026-07-26 — Anchor engine: the diff is advisory, resolution is authoritative (SERVER-002 FAIL-1).** `diff_cleanupSemantic` can merge two neighbouring rewrites into one delete/insert that swallows byte-identical text between them, so `computeOffsetMapper(...).classify` may say `"deleted"` for a range whose characters survive verbatim. SPEC §6 defines an orphan as a selector that _no longer resolves_ — so `reconcileAnchors` verifies every `deleted` (or whitespace-degenerate) claim before orphaning. **Round-2 amendment (FAIL-2): verification is exact-tier only, never fuzzy.** The full-ladder version let fuzzy rung 3 "verify" genuinely deleted text via any ≥75%-similar sibling (lists, tables, parallel paragraphs), silently misattaching threads. A deleted-claim re-attaches only when `resolveAnchorExact` (rungs 1–2) finds the text in `newBody` **and** the match overlaps text this edit inserted (`OffsetMapper.touchesInsertion`) — an exact match wholly inside unedited text is a pre-existing doppelgänger, not survival, and orphans with the selector preserved byte-for-byte. Corollaries: cut-and-paste re-attaches (the pasted copy sits in an INSERT segment); `partial` ranges keep trusting the mapper (in-place-edit evidence outranks a verbatim duplicate elsewhere); already-orphaned-in-`oldBody` anchors are never re-attached. Kept-anchor paths run zero extra work — verification only fires on orphan claims, and it never runs fuzzy (all-orphan worst case dropped ~8× when fuzzy left the path).
- **2026-07-26 — Partial-path slices are only as honest as their boundary attribution (SERVER-012).** A DELETE+INSERT replacement whose DELETE straddles a range boundary makes the INSERT unattributable — the mapper hands it wholly to the range, yielding truncated selectors or a neighbour's text (the diff cross-aligns deleted paragraphs against near-identical edited siblings). `OffsetMapper.straddledByReplacement` detects this; reconcile routes such partials through the deleted-claim verification path (exact-only + insertion-overlap, fuzzy never). Deliberately conservative: an edited sibling whose own anchor gets straddled orphans rather than remapping — a visible false orphan beats silent misattachment, and no non-fuzzy evidence can attribute the replacement. Pure boundary-crossing deletions (no INSERT) still remap to the surviving text.
- **2026-07-26 — Reorders are invisible to segment accounting; overlap is the causal proof (SERVER-012 round 2).** Relocated text always arrives as INSERT, and `mapStart`/`mapEnd` are monotone — so a mapped slice can absorb a sibling's relocated paragraph without straddling anything, and no per-segment detector (nor plain self-round-trip: superset windows can be unique) will notice. What monotonicity does guarantee: old-disjoint anchors can only overlap in `newBody` through misattribution, and a rewritten slice capturing a disjoint co-anchor's entire `exact` is quoting that anchor's text. `reconcileAnchors` therefore runs draft → cross-anchor pass (void colliding/capturing rewritten slices; re-place via the adjudicated exact-only chain) → finalize. Nested (already-overlapping) anchor pairs are exempt; verbatim slices outrank rewritten claims. **Round-3 attempt REVERTED (2026-07-26)**: `lacksKinship` (similarity-below-threshold + verbatim-survivor-elsewhere) was tried and reverted — similarity is the wrong discriminator in BOTH directions (eval round 4: it orphaned 67% of legitimate shrink-edits whose original had a verbatim duplicate elsewhere — a regression vs the cross-anchor pass — while still missing 6.5% of plain two-paragraph swaps at ~0.92 similarity; no constant satisfies both TEST-61 and TEST-63). **The substitution class (an anchor handed unrelated text while its own text survives verbatim and uniquely) remains OPEN** — pre-existing, not a round-2 regression. The evaluator's proposed discriminator for the next attempt: does the anchor's own text survive verbatim and uniquely at a location the mapper didn't choose, and is that survivor in INSERT text (relocation → re-attach) vs EQUAL text (pre-existing duplicate → trust the slice if it's a plausible edit, orphan only for unrelated rewrites)? Resolved by user decision (2026-07-26) and implemented in SERVER-013 (2026-07-27): **relocation evidence** — a verbatim occurrence of the anchor's `exact` disjoint from the mapped slice and overlapping INSERT text — voids a rewritten slice without requiring uniqueness (the chain's uniqueness rules orphan on ambiguity); EQUAL survivors keep mapper trust (the corner is closed by the SERVER-002 adjudication, and zero-survivor discrimination is provably vacuous on the partial path: `partial` implies ≥1 surviving character). **Boundary repair**: a rewritten slice snaps to a round-tripping verbatim occurrence of its own `exact` overlapping the mapped range (fixes off-by-punctuation truncation). Substitution measured 319→0 and 309→0 on two seeds, zero flips outside the class, no numeric constants added. Similarity thresholds remain off the table permanently.
- **2026-07-27 — Skills/agent-defs resolve by the name their path encodes, not by `documents.title` (SERVER-006).** The seeded SKILL.md carries Claude Code's `name:` AND Corpus's `title:` in one frontmatter, and the projection has no `name` column — `/comment`-style invocation lookup must index `invocableName(path)` (case-insensitive) alongside the title or it resolves to nothing.
- **2026-07-27 — chokidar must watch a watched file's parent to see it APPEAR (SERVER-006).** Watching `.corpus/seen.json` does nothing for a not-yet-existing file when the dot-prefixed `.corpus` directory is ignored — the ignore predicate must exempt each watched file's parent directory. A fixture that seeds the file first hides the bug completely; the regression test must start file-absent.
- **2026-07-27 — Projection rebuild swaps the connection under a stable handle (SERVER-017).** Every consumer (docs routes, lock service, job service, watcher, queue mirror) captures the `ProjectionDb` **object** at mount time, so a rebuild must never mint a new handle — `ProjectionDb.reopenAround(replaceFile)` closes the connection, runs the file replacement, and reopens at the same path, with the connection behind a closure (`get sqlite()`, `prepare` memoized against it). Ordering is load-bearing: `rebuild()` deletes the destination's `-wal`/`-shm` after its rename, and a connection still open on the unlinked inode can recreate a stale WAL _by path_ over the fresh database — close-before-replace is enforced structurally by taking the replacement as a callback. Both sides are synchronous, so no request can interleave and no mutex is needed. The mirror rebind after rebuild re-runs the queue reader's directory scan (the authority on `events`). Corollary for drift E2E: the watcher heals out-of-band _file_ edits within ~1 s, so `db doctor` drift must be induced in the projection rows, not the files.
- **2026-07-27 — `["tree"]` is decided by measurement, not by call sites (SERVER-018).** Seven hand-pushed `TREE_KEY` sites disagreed with `docs/tree.ts` about what moves a folder badge (parented threads count in the parent's folder; an archived doc counts nowhere but its threads still do; deleting a doc un-counts its orphaned threads) — archive/unarchive was silent on three routes while standalone-thread deletion over-announced. The fix: `MutationPlan.mayChangeTree` + `runMutation` comparing `folderTreeSignature()` (JSON of the same `folderTree(db)` that answers `GET /api/tree`) across the re-projection, appending `TREE_KEY` iff it changed. Set `mayChangeTree` only when the write can plausibly move a badge (`update.ts`: only status-changing patches) to keep the extra query off the autosave path. The watcher's `flush()` still uses a structural heuristic and violates the invariant both ways — SERVER-020.
- **2026-07-27 — The WHATWG URL parser rewrites traversal before your handler runs (SERVER-010).** `new Request(url)` resolves `.`/`..` and maps `\`→`/` before routing, so a raw `/attachments/../x` never reaches the `/attachments/*` handler — it either falls through to the UI shell (200) or, worse, gets _rewritten into a different valid attachment path_ and served. Path-prefix guards must read the unnormalized target off `c.env.incoming.url` (`createRawAttachmentPathGuard()`), and every refusal class (raw, encoded, double-encoded, backslash, absolute, NUL, symlink, nonexistent) must share one uniform 404 — no existence oracle. Companion decisions: case sensitivity is decided, not inherited (macOS `realpath` does NOT canonicalize case — require each component byte-for-byte in its parent's `readdir`, same 404 on macOS and Linux); symlinks are refused via `lstat` + `O_NOFOLLOW` at open (closes the check-to-open window); name-collision dedup must shrink the _stem_ to make room for the `-<n>` marker (truncating the built candidate back to the cap returns the original at cap length → unbounded loop inside a request handler).
- **2026-07-26 — YAML serializers never restore source whitespace (SERVER-001 FAIL-2).** The `yaml` package preserves comments, key order, and scalar quoting across an AST mutate → `toString()` cycle, but source-level whitespace (flow-collection spacing, nested indent width, colon padding) is not in the AST at all — no AST-level API can preserve it. Any mutation path that must keep diffs minimal has to splice untouched keys' lines verbatim from the original source and treat the full re-emit as a fallback, guarded by a re-parse equivalence check (`setFrontmatterFields` does exactly this; shapes a line-oriented split can't honestly describe — flow mappings, `? key`, collection-as-key — degrade to re-emit).
